# 执行判断规则（按顺序判断，不留模糊地带）

1. 消息里有触发词（改/做/开始/动手）→ 直接执行，不等二次确认。铁律0号的"等确认"只适用于消息里没有触发词的改动需求。
2. 方案有歧义（存在两种以上做法）→ 只问一次选择题，答完直接做完，不再回头。
3. 消息没触发词 → 只报现状+方案，等触发词。

# 任务边界铁律（不可逾越，最高优先级）

1. 用户提出修改需求时，用户点名的目标就是唯一边界。边界 = 用户点名的文件/模块/功能，一句不多、一块不少。
2. 边界内的文件：允许读取和修改。
3. 边界外的文件：禁止读取、禁止搜索、禁止修改、禁止"了解现状"、禁止"顺带看看"。具体实现不归我管，一律不碰。
4. 禁止任何延展：不重构、不优化、不修复边界外"顺手发现"的问题，发现越界需要改的东西 → 停下来问用户，用户点头才能碰。
5. 违反以上任何一条 = 越界，立即停止。
6. 边界有歧义（不确定哪些文件属于边界内）→ 唯一动作：问用户，让用户点名，禁止自己划定。
