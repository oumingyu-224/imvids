# 工作台页面优化计划（按模型动态参数 + kie/fal 对接）

> 本计划供新对话执行使用。模型与 kie/fal 入参事实来源：`价格修改/模型清单.md`。

## 一、目标

工作台图片页 / 视频页：切换模型时，参数表单跟随模型变化；提交时按渠道（kie / fal）正确组装参数。

## 二、硬性约束（必须遵守）

1. 现有通用参数控件（宽高比、清晰度、参考图上传、时长、生成数量等）**全部保留，不得删除重建**。
2. 只做增量：models.ts 加「差异配置」，页面控件按配置做显示/隐藏/裁剪选项，没有配置的模型走现有通用行为。
3. 不动计费、不动价格页、不动其他页面。
4. 三个已隐藏模型（veo-3-1-basic、veo-3-premium、veo-3-basic）保持隐藏，不为其配置参数。

## 三、涉及文件

- `src/shared/blocks/generator/models.ts` — 模型定义，加差异配置字段
- `src/shared/blocks/generator/image.tsx` — 图片页表单渲染 + 提交
- `src/shared/blocks/generator/video.tsx` — 视频页表单渲染 + 提交（含 SEEVIDEO_VIDEO_MODEL_MAP 渠道映射）
- `src/app/api/ai/generate` 对应路由 — 提交层参数组装（kie 包 `input`，fal 平铺）

## 四、实施步骤

### 第 1 步：定义差异配置结构（models.ts）

给 `GeneratorModel` 接口增加可选字段（保持向后兼容，不填 = 走通用默认）：

- `paramOverrides`：控件级覆盖，按控件 key（如 aspect_ratio / resolution / duration / refImages / outputCount / generateAudio）声明：
  - `hidden: boolean` — 隐藏该控件
  - `options: string[]` — 裁剪后的可选值列表
  - `maxCount: number` — 参考图/数量上限
  - `mapTo: string` — 提交时的实际字段名（同一控件不同模型字段名不同）
- `provider` / `endpoint`：渠道标识与 fal endpoint id（fal 渠道模型用）

### 第 2 步：图片页改造（image.tsx）

1. 渲染：取当前模型的 `paramOverrides`，无配置 → 现有行为不变；有配置 → 隐藏/裁剪对应控件。
2. 提交：按模型配置组装参数——
   - kie 渠道：`POST /api/v1/jobs/createTask`，`model` = 该模型 kie model 值，参数装进 `input`，字段名按 `mapTo` 转换。
   - fal 渠道：调 fal endpoint，参数平铺（不包 `input`）。
3. 校验按配置执行：参考图上限（nano-banana-pro / nano-banana-2 为 8）、清晰度与宽高比组合限制。

### 第 3 步：视频页改造（video.tsx）

同图片页方式：控件保留、按配置渲染、按渠道组装。注意每个视频模型可能有多个 kie model 值（文生/图生/参考生各一个），提交时按是否有参考图/首帧自动选对应 model 值（映射见模型清单）。

### 第 4 步：逐模型配置差异（按模型清单.md 事实）

图片模型差异要点：

- gpt-images-2-5-flare：aspect_ratio 选项限其枚举；有 background 控件；图生图用 input_urls
- seedream-5-lite：无清晰度 4K 区分时用 quality（basic/high/ultra）；aspect_ratio 限其枚举
- seedream-4：字段名映射 aspect_ratio→image_size、resolution→image_resolution；有张数 max_images
- nano-banana：aspect_ratio 含 auto；有 image_size、output_format
- nano-banana-pro / nano-banana-2：参考图上限 8；resolution 1K/2K/4K
- qwen-image-edit：num_images（1–4）；image_url；可选进阶项（negative_prompt、guidance_scale 等，默认隐藏可不做）
- grok-imagine-image：aspect_ratio 限 1:1/2:3/3:2/16:9/9:16；图生图 image_urls
- gpt-4o-image：专用接口（非 Market），字段 files_url，单独分支
- flux-kontext-pro / max：专用接口 flux-kontext-api，字段 input_image；max 有 fal 备选 endpoint

视频模型差异要点：

- gemini-omni-flash-1-1 / gemini-omni：duration（4/6/8/10）；resolution 档位不同（前者含 360p）；首尾帧字段 first_frame_url / last_frame_url
- minimax-h3：图生视频 first_frame_url/last_frame_url、resolution（768P/2K）；文生视频 aspect_ratio；duration 4–15
- minimax-h3-max-turbo、ltx-2-5-fast：kie 无文档，走 fal endpoint（清单已列）
- seedance 系列（2.5 / 2.0 / fast / mini / 1.5-pro）：duration、resolution 档位各异（fast/mini 仅 480p/720p）、generate_audio、首尾帧 + 参考图
- pixverse-v6：quality 即分辨率（360p–1080p）、generate_audio_switch、image_urls、参考生 image_references
- veo-3-1-premium：专用接口 veo3-api，generation_type 按模式选；model 值 `veo-3-1`
- veo-3-1-lite：fal endpoint（清单已列）
- wan-3-0 / 3-0-prime：resolution（480P/720P/1080P）、audio、参考图/视频/音频
- wan-2-5：duration（5/10）、resolution（720p/1080p）、图生 image_url
- kling-2-5 / 2-1-master / 2-1-pro：duration（5/10）、image_url、tail_image_url（尾帧）
- grok-imagine-video：mode（fun/normal/spicy）、resolution（480p–1080p）、image_urls
- runway-gen-4：专用接口 runway-api，model 值 `runway`，quality 字段

### 第 5 步：自查

- 每个模型：切换后表单项正确、提交 payload 字段名与模型清单一致
- 未配置差异的模型行为与改前一致
- 隐藏的三个模型不出现在选择器

## 五、文档缺失/特殊项（执行时注意）

- `gpt-4o-image`、`flux-kontext-pro/max`、`veo-3-1-premium`、`runway-gen-4` 走 kie 专用接口，不是 Market 统一 createTask 结构
- `minimax-h3-max-turbo`、`ltx-2-5-fast` 走 fal
- Kling 2.5 的 kie 文档 model 值与页面标题不一致（清单第 20 条），执行时以后台实际可用为准
- fal 渠道需要独立 key 与鉴权，确认后台已配置后再接

## 六、验收方式

用户线上自行验证：逐个切换模型，确认表单变化与提交成功；不改完跑 build / 测试。
