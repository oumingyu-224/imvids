# 模型页面制作工作流

> 目标：每个模型页在**同一套组件、同一个 json 结构**下，长出**完全不同的内容身体**。
> 核心纪律：**一页一手工制作，严禁用脚本/代码一次性批量生成正文。**
> 样板：`seedance-2-5`（视频模型，"一镜到底"角度）与 `gpt-images-2-5`（图片模型，"文字必须对"角度）。

---

## 一、为什么禁止代码批量生产

- 谷歌对「模板化近重复」（doorway page / thin content）有专门检测：12 个页面若只有模型名和积分数字不同、句式节奏一样，整组互相稀释，重则连坐降权。
- 代码生成的本质是"同一份正文换变量"，它能保证结构一致，但**永远保证不了内容角度差异**——而差异化恰恰只来自人工逐页思考。
- 结构统一没问题（HTML 骨架不是惩罚对象），惩罚的是内容。所以：**组件和 json 字段结构可以完全一致，正文必须逐页手写。**

---

## 二、固定不变的东西（工程层，所有页面相同）

1. **组件**：全部走 `LandingPageRenderer`，不为任何页面单独写组件。
2. **文件位置**：每页一个 json——`src/config/locale/messages/en/models/<slug>.json` + `zh/models/<slug>.json`（en/zh 双语）。
3. **路由**：根级扁平 slug（`/seedance-2-5`），`src/app/[locale]/(landing)/<slug>/page.tsx` 走统一模板。
4. **json 顶层字段**（顺序固定）：
   ```
   metadata → generator → hero → usage → features → testimonials → faq → cta
   ```
5. **注册**：`src/config/locale/index.ts` 注册 `models/<slug>` 命名空间；`src/config/landing-pages.ts` 用 `modelPageConfig` 工厂加配置；`src/app/sitemap.ts` 收录。
6. **H1**：`generator.title` 即工作台 H1，格式「模型名 + Generator」，一页唯一。

---

## 三、每页必须重新做的东西（内容层，逐页手写）

### 第 1 步：搜索该模型的真实特性

用 WebSearch 搜该模型的官方发布信息，重点收集：
- 输入方式（文生/图生/参考图/首尾帧/音频驱动……）
- 硬参数（时长上限、分辨率档位、参考数量、prompt 上限、画幅数量、延迟）
- 独家能力（别的模型没有的那一条，这就是页面差异化核心）
- 相对上一代/竞品的差别（对比内容来源）

**样板对比**：
| | Seedance 2.5 搜到的独有卖点 | GPT Images 2.5 搜到的独有卖点 |
|---|---|---|
| 核心能力 | 30 秒一镜、Shot 1/Shot 2 分镜、50 个多模态参考（30图+10视频+10音频）、时间戳导演、局部编辑、10+ 语言口型 | 引号内文字忠实渲染、Flare 快速版、局部编辑、透明背景、13 画幅、20000 字符 prompt、1K-4K 同价 |

### 第 2 步：取本平台真实数字（只许两个来源，一个都不许编）

- **能力/参数**：`src/shared/blocks/generator/models.ts`
- **积分/价格**：`src/config/locale/messages/en/pages/pricing.json` 的 `pricing.models.items`（每次生成积分）和 `pricing.items`（档位：Starter $29.99/2500、Pro $89.99/10000、Unlimited $149.99/15000）
- 平台里查不到的数字（注册赠送积分、试用天数、是否绑卡）**直接不写**，宁可缺失也不编造——AI 会把假数字当事实摘抄出去。

### 第 3 步：定本页的内容角度（这步是差异化的灵魂）

先回答一个问题：**这个模型解决的最痛的一件事是什么？** 答案就是本页主题，其余全部围绕它。

- Seedance 2.5 → 「一条完整镜头胜过四段拼接」→ 叙事/广告制作角度
- GPT Images 2.5 → 「有些图，字错了就全废」→ 印刷级文字角度

角度定了，后面每一块的标题、步骤叙事、FAQ、评价人物全部顺着这个角度写，自然就不同。

### 第 4 步：按角度手写 json（en 先写，zh 再独立成稿，不逐句直译）

逐块的差异化手段（全部是 json 层面，不碰组件）：

| 块 | 必须差异化的点 |
|---|---|
| `metadata` | title 带本页角度（"30-Second One-Take" vs "Where the Text Comes Out Right"），不是模板句式 |
| `hero.description` | 首句用本页主题句；角度决定口吻 |
| `hero.trust_items` | 3 条全部换成该模型的硬参数，互不重复 |
| `usage.title / description` | 标题是本页工作流的名字（"One Prompt to a Shot List" vs "From Brief to Render"），四步叙事贴合模型使用方式 |
| `usage.items` | 每步一句说明贴模型真实操作；条数可 3~5 条浮动 |
| `features` | **条数每页不同**（样板 5 条 vs 4 条）；每条 = 该模型一条真实能力 + 它消除的痛点；标题写成果不写功能名 |
| `testimonials` | 职业按模型的使用人群换（广告监制/短剧导演 vs 美术指导/包装设计师）；引言里自然带平台积分数字 |
| `faq` | 6 条中**至多 2 条**价格通问，其余全是模型专属问题（"多镜头脚本怎么写" "图内文字能准吗"）；对比题（X vs Y）单独一条 |
| `cta` | 标题复用本页主题句变体，不复用模板句 |

### 第 5 步：验证

1. 4 个 json（如做双语）语法校验通过。
2. 数字核对：页面上出现的每个数字都能在 models.ts / pricing.json / 搜索结果中找到出处。
3. 差异自检：把本页和任一其他模型页放一起，肉眼比较——usage 标题、features 条数、FAQ 问法、评价人物，四处至少有四处不同才算过。

---

## 四、FAQ 写作铁律（AI 摘抄的入口，不许自由发挥）

每条答案四个条件：
1. **自包含**：去掉问题单独看也成立；主语写模型名/Oddbeam，不写"该产品""我们"。
2. **带数字**：积分、时长、分辨率、价格、版本号——至少一个。
3. **2~3 句，先结论后理由**。
4. **问法用用户真实搜索的说法**：is it free / how much / can I use commercially / what's the difference between X and Y。

合格样例（Seedance 2.5）：
> Q: How much does Seedance 2.5 cost per video?
> A: Seedance 2.5 costs 160 credits per generation at the standard rate on Oddbeam. Unlimited plan subscribers pay 80 credits per clip, and yearly Unlimited brings it to 64. The Starter plan at $29.99 per month includes 2,500 credits — enough for about 15 Seedance 2.5 clips.

## 五、数据源清单（写每页之前先查这三处）

| 要什么 | 去哪拿 |
|---|---|
| 模型输入方式/时长/分辨率/参考数 | `src/shared/blocks/generator/models.ts` |
| 每次生成积分 | `pricing.json → pricing.models.items[].credits` |
| 档位价格与月积分 | `pricing.json → pricing.items[]` |
| 模型真实特性、与竞品差异 | WebSearch 官方发布信息 |

注意事项：
- 导航「模型」下拉与模型页清单必须与 pricing.json 模型表严格一致——平台没有真实数据的模型（如 Qwen Image Edit、Grok Imagine Image）不进下拉、不建页；替换进来的模型必须是 pricing.json + models.ts 双源都有的（2026-10 已换入 Seedream 4.0、Nano Banana 2、Seedream 5.0 Lite）。
- 每个模型的积分以 `pricing.json → pricing.models.items[].credits` 为准，Unlimited（premium）档的免费/折扣价也要写明。

---

## 六、禁止清单

- ❌ 用脚本/Python/循环批量生成任何页面的正文
- ❌ 复制另一页的 json 改模型名交差
- ❌ FAQ 全站同一套问法（"Is X free to try?" 最多全站出现结构相似，问句内容必须贴模型）
- ❌ 编造任何数字（价格、额度、天数、参数）
- ❌ 每页 features 条数、FAQ 数量、章节叙事全部一样
- ❌ 把 "keyword" 这类词写进用户可见文案

---

## 七、验收标准（每页做完过一遍）

1. 同模板下与任一其他模型页对比：标题口吻、usage 叙事、features 条数与内容、FAQ 问法、评价人物——**至少四处明显不同**。
2. 全部数字可溯源（models.ts / pricing.json / 官方发布）。
3. 禁用 JS 后 FAQ 答案可见（服务端渲染已由 faq.tsx forceMount 保证，json 只管内容）。
4. JSON 语法校验通过，en/zh 双语齐全。
